The LLM client provides a shared Java API for OpenAI-compatible endpoints, Anthropic and the ChatGPT-subscription Codex backend.
`io.yupiik.ai:llm-client` is the parent project; applications use the API and provider artifacts below.

== Getting started

Add the provider module for your endpoint.
For example, use this dependency for OpenAI Chat Completions or Responses:

[source,xml]
----
<dependency>
  <groupId>io.yupiik.ai</groupId>
  <artifactId>llm-client-openai</artifactId>
  <version>1.0.0-SNAPSHOT</version>
</dependency>
----

Provider modules bring in `llm-client-api`, which defines the shared request and response types.
Use a shared Fusion `JsonMapper` and `ExtendedHttpClient` supplied by your application.
Keep them open while requests run and let their owner close them; client wrappers do not take ownership.

== Send a request

Configure the provider's full chat endpoint and credentials, then wrap its dialect in a `DialectLlmClient`.
For example, with an already configured `OpenAICompletionsDialect` named `dialect`:

[source,java]
----
try (final var llm = new DialectLlmClient(dialect, LlmResilienceConfig.defaults(), null)) {
    final var request = LlmRequest.of(
            "gpt-4o", List.of(LlmMessage.user("Hello")));
    System.out.println(llm.chat(request).toCompletableFuture().join().text());
}
----

The xref:llm-client-openai.adoc#_usage[OpenAI usage example] shows how to construct that dialect with an API key.
Use the xref:llm-client-anthropic.adoc[Anthropic module] for `x-api-key` authentication or the xref:llm-client-codex.adoc[Codex module] for ChatGPT OAuth enrollment.
The xref:llm-client-api.adoc[API guide] covers streaming, routing, resilience and the provider SPI.
