= Tasks
:minisite-nav-prev-label: Executors
:minisite-nav-prev-link: executors.html
:minisite-nav-next-label: Updates
:minisite-nav-next-link: updates.html

A task is the unit of work of A2A: a caller sends a message, the agent creates a task, and the task carries the state
until it ends.

== The lifecycle

[source,text]
----
SUBMITTED ──▶ WORKING ──┬──▶ COMPLETED   terminal
                        ├──▶ FAILED      terminal
                        ├──▶ CANCELED    terminal
                        ├──▶ REJECTED    terminal
                        ├──▶ INPUT_REQUIRED   interrupted, the caller answers to resume
                        └──▶ AUTH_REQUIRED    interrupted, the caller authenticates to resume
----

[options="header",cols="1,3"]
|===
| Kind | Meaning
| terminal | the task will never change again. It refuses further messages - `UnsupportedOperationError` - and cannot be canceled - `TaskNotCancelableError`.
| interrupted | the task is waiting for the caller. The next message referencing it resumes it, on the same identifier.
|===

`TaskState#isTerminal()`, `isInterrupted()` and `isSettled()` express those three predicates, on both sides of the wire.

== Identifiers

[options="header",cols="1,3"]
|===
| Field | Rule
| `taskId` | *server generated*, always. A caller sending an unknown one gets `TaskNotFoundError`; it may never invent one.
| `contextId` | groups the tasks and messages of one conversation. The agent generates it when the caller sends none, and a caller may reuse it to start a new task in the same conversation.
|===

Sending a `contextId` which does not match the referenced task is rejected with an `InvalidParamsError`, as the
specification requires.

== A multi-turn conversation

[source,bash]
----
# 1. the caller asks something incomplete
curl -X POST http://localhost:8080/a2a -H 'content-type: application/json' -H 'a2a-version: 1.0' -d '{
  "jsonrpc": "2.0", "id": 1, "method": "SendMessage",
  "params": {"message": {"messageId": "m-1", "role": "ROLE_USER", "parts": [{"text": "book a flight"}]}}}'
----

[source,json]
----
{
  "result": {
    "task": {
      "id": "t-1",
      "contextId": "c-1",
      "status": {
        "state": "TASK_STATE_INPUT_REQUIRED",
        "message": {
          "role": "ROLE_AGENT",
          "parts": [
            {
              "text": "From where to where?"
            }
          ]
        }
      }
    }
  }
}
----

[source,bash]
----
# 2. the caller answers on the same task, which resumes it
curl -X POST http://localhost:8080/a2a -H 'content-type: application/json' -H 'a2a-version: 1.0' -d '{
  "jsonrpc": "2.0", "id": 2, "method": "SendMessage",
  "params": {"message": {
    "messageId": "m-2", "taskId": "t-1", "contextId": "c-1",
    "role": "ROLE_USER", "parts": [{"text": "Paris to New York"}]}}}'
----

The task keeps its identifier, its history and the artifacts it already produced. On the server side each message opens a
new *turn*: a fresh pair of promises, so the second call is never answered with the result of the first.

== History

Every message - the incoming ones and the status messages the agent attaches - is appended to the task history. A caller
decides how much of it comes back:

[options="header",cols="1,3"]
|===
| `historyLength` | Result
| unset | the whole history
| `0` | the `history` attribute is omitted entirely
| `n > 0` | the `n` most recent messages
|===

It is honored by `SendMessage` - through `configuration.historyLength` - `GetTask` and `ListTasks`.

== Listing

`ListTasks` finds tasks again: after a restart of the caller, to build a dashboard, or to reconcile.

[source,bash]
----
curl -H 'a2a-version: 1.0' 'http://localhost:8080/a2a/v1/tasks?contextId=c-1&status=TASK_STATE_WORKING&pageSize=20'
----

[options="header",cols="1,3"]
|===
| Parameter | Behavior
| `contextId` | only the tasks of that conversation
| `status` | only the tasks in that state, a `TASK_STATE_*` name
| `statusTimestampAfter` | only the tasks updated at or after an ISO-8601 instant
| `pageSize` | `50` by default, `100` at most
| `pageToken` | the cursor a previous call returned. `nextPageToken` is an *empty string* on the last page, never `null`
| `historyLength` | how much history per task
| `includeArtifacts` | `false` by default - the `artifacts` attribute is then omitted, to keep the payload small
|===

Tasks come back sorted by status timestamp, most recently updated first.

== Cancellation

[source,bash]
----
curl -X POST http://localhost:8080/a2a/v1/tasks/t-1:cancel -H 'a2a-version: 1.0'
----

Cancellation is cooperative: the server asks the xref:executors.adoc[executor] to stop and concludes the task itself if
the executor does not. It is idempotent on a running task and answers `TaskNotCancelableError` on a terminal one.

== Retention

Tasks live in memory and are dropped once they have not been touched for `fusion.a2a.taskRetention` - `PT30M` by
default, `0` keeps them forever. The eviction runs when a task is created, so no background thread is needed, which
keeps a native image simple.

A dropped task answers `TaskNotFoundError`, which the specification explicitly allows: "it might be invalid, expired, or
already completed and purged". Raise the retention if your callers poll long after the fact, and see
xref:../internals/design.adoc[Design] for what to change to store them elsewhere.
